# 分阶段开发路线图

## 执行规则

阶段严格按顺序推进。每次只实现当前阶段一个可验收切片；满足退出条件后更新本文件的状态与 `GOAL.md` 检查项。不得为了未来能力预建大规模抽象。

## Phase 0：工程基线 ✅（2026-09-09 完成）

**目标**：得到可重复构建、测试和导航的空壳。

任务：

- 初始化 Flutter 项目、Android/iOS 配置和固定应用 ID。
- 接入格式化、静态检查、Riverpod、go_router、Drift 和测试框架。
- 建立主题、错误模型、时钟/ID 抽象、基础路由与五个占位页。
- 建立 CI 或本地统一验证脚本：format、analyze、test。
- 添加开发模式隐私日志过滤器。

交付物：可安装 Debug 包、自动化验证命令、基础目录。

退出条件：干净环境能按 README 构建；静态检查与样例测试通过；导航无崩溃；日志测试证明敏感字段被过滤。

## Phase 1：本地档案与营养记录闭环 ✅（2026-09-10 完成）

**目标**：完全离线完成建档、手动记餐和今日统计。

任务：

- 数据库初始化、迁移和安全密钥管理。
- 引导建档、目标计算与安全边界提示。
- 导入最小食物种子库，实现搜索、自建食物、份量换算。
- 餐食/条目 CRUD、历史复用、撤销删除。
- 今日页热量与三大营养素进度。
- 体重记录和 7 日移动平均。

退出条件：飞行模式下可完成全流程；重启不丢数据；单位计算和目标计算单测通过；历史营养不会因食物库更新变化。

验收记录：本地档案、目标、食物、餐食营养快照、今日统计和体重已通过宿主机普通 SQLite 文件关闭/重开测试；该测试不替代生产 SQLCipher 验证。运行时 Phase 1 流程无网络依赖，Android 主清单不声明联网权限。Android SQLCipher 同密钥重开、错密钥拒绝、飞行模式和进程杀死仍需在有真机时完成，并保留为发布门槛。

## Phase 2：AI 拍照记餐

**目标**：实现“拍照—候选—修正—入账”核心卖点。

任务：

- 相机/相册选图与权限处理。
- 图片方向修正、去 EXIF、压缩和临时文件生命周期。
- AI Provider 接口、严格 JSON v1 解析、配置 URL 规范化和单一 hardened OpenAI 兼容数据层实现（已完成）。
- base URL、模型和 API Key 本地设置；每次上传前展示规范化目的地、模型、当前图片摘要及去 EXIF/临时传输边界，且只在用户明确确认后发送（已完成）。
- HTTP 错误分类、超时、基础设施无关取消和显式用户手动重试；首版不自动重放照片 POST，取消/错误保留预览（已完成）。
- 候选食物本地匹配、置信度/范围、追问与编辑界面（已完成）：仅唯一规范化精确匹配可预选，营养仅由选定本地食物重算；候选仅在内存中，歧义/弱匹配/未匹配项必须人工选择。
- 用户最终确认后事务保存，取消时不进入统计，并在成功后清理临时图片（已完成）：仅全部候选明确选定本地食物并具备有效克数时可确认；通过 `MealRepository.create(source: 'ai_scan')` 原子保存餐食/营养快照，保存失败或取消均保留候选和预览；成功后才删除临时图片并由今日营养流更新统计。

退出条件：正常、无网、401、429、超时、非法 JSON、空结果均有可恢复体验；API Key 不出现在数据库/日志；测试图片从选择、候选修正、最终确认到本地保存、临时图片清理和今日统计更新的端到端流程通过。

## Phase 3：食谱与饮食计划

**目标**：生成可执行计划并复用现有记餐能力。

任务：

- 本地食谱 CRUD、份数缩放、营养重算（已完成首个离线切片）：食材仅可选择本地食物库，创建/更新在事务中重算条目快照，食谱删除级联条目但不影响历史餐食；目标份数缩放只供展示，不改写保存记录。
- 本地周计划 CRUD（已完成第二个离线切片）：在既有食谱页安排已保存食谱到日期/餐次，保存食谱名称、计划份数与缩放营养快照，支持编辑、删除和撤销。计划条目独立于 `meals` / `meal_items`，不计入已摄入或今日统计。
- AI 食谱计划请求和结构化结果校验（已完成第三个子切片）：每次文本请求前披露目的地主机、Base URL、模型及天数/餐次并等待确认；独立的 text-only OpenAI-compatible Provider 严格解码 schema-v1，草案仅驻留内存。本地只对唯一匹配食物重算营养，未知/歧义食材保持未解析；结果不能写入 `recipes`、`meal_plan_entries`、`meals` 或 `meal_items`，也不改变已摄入统计。
- 本地饮食偏好与过敏原限制（已完成第四个子切片）：schema v5 将档案级偏好与过敏原避开项分开保存；食物使用明确知识状态、标准标签和过敏原事实，旧食物默认未知，种子库 v2 提供有限可审计事实。每次 text-only 请求前披露将发送的限制；本地唯一匹配后才核验，已知冲突、未知事实和未解析项均不能被称为安全可启用。草案继续没有持久化/启用路径，也不改变已摄入统计。
- 本地预算、草案声明时长和库存/食材约束（已完成第五个子切片）：schema v6 保存可选预算最小货币单位/币种、每餐草案声明时长上限、库存核验开关，以及按 `food_id` 的本地每 100g 价格和库存克数；所有事实均由用户显式保存且不发送给 AI。预算仅使用唯一匹配、同币种的本地价格，库存跨整个草案聚合克数，缺失、歧义、币种不兼容或不足不会被称为通过；时间只比较模型声明分钟数而非实际烹饪时长。新结果不扩展现有饮食/过敏原安全布尔值，也不启用或持久化草案。
- 周计划食谱替换与采购清单合并（已完成第六个本地切片）：用户可仅替换单个计划条目的本地食谱，保留日期、餐次和计划份数，由现有更新事务刷新食谱/营养快照和版本，不修改旧食谱、不创建餐食也不影响统计。周采购清单仅在内存中按所选周的计划条目与其引用食谱**当前**保存的食材构成，以具体 `food_id` 汇总缩放克数并显示来源；缺失当前食谱或无效构成必须显式提示，不能静默遗漏。库存已知时只展示本地记录的缺口，库存未知仍是未知；本地价格仅对已知缺口按币种分别向上取整估算，缺价保持不完整。清单不持久化、不扣减/预留库存、不提供实时/零售价格、包装换算、购买建议或自动同类/食材替换。
- 本地食谱确认记餐（已完成第七个本地切片）：用户选择日期、餐次和食用份数后查看重新加载的食谱条目快照及缩放营养，明确确认才通过 `MealRepository.create(source: 'recipe')` 原子创建恰好一条餐食与条目快照，并更新对应日期已摄入营养；取消、缺失食谱或无效份数不写餐食。操作不调用 AI、不变更 `meal_plan_entries`，也不扣减或变更 pantry 库存。
- 计划草案需用户确认后启用（已完成第八个本地切片）：外部生成披露不等同于本地写入授权；用户选择 Day 1 日历日期并为每道食谱确认成品重量后，重新按当前本地食物和规划事实核验，饮食/过敏限制按生成时所选与本机当前保存限制的并集评估（限制更新只会收紧、不会放宽）。草案必须具有完整唯一的请求日/餐次形状；任一已有日期/餐次计划冲突会阻止整份导入。最终确认以一个外层事务原子创建全部本地食谱、条目和周计划条目，不创建餐食、不更新已摄入、不修改库存/价格。预算、库存和声明时长保持可见参考；当前不持久化步骤、声明时长、警告、提供商来源或导入分组，并明确告知用户。

退出条件：所有营养值由本地库重算；过敏冲突、未知限制事实、未匹配食材和日期/餐次冲突不能启用草案；修改份数后克数和营养一致；整份草案启用原子创建食谱和计划条目而不创建历史餐食、改变已摄入统计或库存/价格；食谱确认记餐使用保存快照而非后续变更的基础食物数据，确认后仅新增一餐并更新对应日统计，计划和库存保持不变。

## Phase 4：训练计划与执行

**目标**：完成训练计划、逐组记录和进步统计。

切片顺序：① 最小动作库（已完成）→ ② 手动训练计划（已完成：schema v8 新增 `workout_plans` / `workout_days` / `planned_exercises`，本地创建计划、按星期安排动作与组次目标，添加/移除/删除计划均在事务内执行并校验动作存在与正整数组次）→ ③ 今日训练与组次记录（已完成：schema v9 会话/组次两表，同一时刻仅一个进行中会话，可从中断处恢复；逐组记录重量/次数/可选 RPE，休息倒计时按挂钟时间戳计算、后台恢复不漂移；删除计划不会破坏已有会话）→ ④ 训练容量、个人纪录与周完成率（已完成：`TrainingStatsCalculator` 纯 Dart 计算本周容量（已结束会话的重量 × 次数）、按动作最重组次记录（同重量取次数更多者，未来会话不计入）、以及按计划星期与已结束会话推导的周完成率（未到期训练日不计入分母，无到期日为空）；计划视图展示本周容量卡片与个人纪录，计划详情展示本周完成率）→ ⑤ 规则化渐进建议与疼痛反馈安全提示（已完成：`ProgressionAdvisor` 纯 Dart 规则引擎按动作对比上次已结束训练的最重组次，输出「小幅增加/保持/暂无历史」三类保守提示（杠铃+2.5kg、哑铃+2kg、器械绳索+5kg、自重+1 次；RPE≥9.5 或退步时保持），明确标注仅供参考；会话内「疼痛反馈」仅提供停止训练、降低负荷、替换动作三项通用选项并提示咨询专业人士，停止训练会立即结束会话）→ ⑥ AI 训练计划（已完成：披露→生成→严格校验→本地确认，仅引用已有动作 ID）。Phase 4 退出条件已满足：中断后可恢复训练；计时按挂钟、后台恢复正确；个人纪录和容量计算单测通过；未知 AI 动作被拦截。。AI 训练计划仅在上述手动闭环稳定后引入，且仅可引用已存在的动作 ID。

任务：

- 最小动作库、搜索和替代动作（已完成第一个本地切片）：schema v7 引入 `exercises` 表并迁移既有库；种子库 v1 提供 24 个经审计的基础动作，导入器验证版本与枚举值并幂等写入。训练页提供本地名称搜索、用户自建动作（名称非空校验，自建动作排序优先）和同肌群替代动作查询。动作库完全本地，不涉及网络，也不创建任何训练记录；训练计划与逐组记录仍在后续切片。
- 手动训练计划（已完成第二个本地切片）：schema v8 新增计划/训练日/计划动作三表，用户可创建命名计划、按星期 1..7 添加本地动作并设置正整数组次目标与可选目标重量；条目添加与移除在事务内执行并递增修订版本，移除后自动清理空训练日，删除计划级联清理全部内容。不合法名称、重复星期、未知动作与非正组次全部拒绝写入。计划与动作库都在训练页的分段视图中，仍不创建任何训练会话或统计。
- 手动及 AI 训练计划；AI 仅引用已有动作 ID（AI 部分已完成第六个本地切片）：AI 训练计划使用独立 BYOK 文本请求，发送前披露目的地主机、模型与发送内容（动作库动作 ID 与名称、每周天数、目标文字），确认后调用 hardened OpenAI-compatible Provider。结果按训练计划 schema-v1 严格解码：完整且唯一的星期集合、恰好请求的天数、每个 `exercise_id` 必须存在于本地动作库（未知或杜撰动作拒绝整份草案）、正整数组次与非负可选重量。草案只在用户本地确认后以 `source: 'ai'` 写入，绝不自动启用或产生训练记录。
- 今日训练、组次记录、RPE、休息计时、完成反馈（已完成第三个本地切片）：从计划任意训练日开始会话，逐组记录重量、次数与可选 RPE；同一时刻仅允许一个进行中会话，中断后通过「继续训练」恢复；每记录一组自动开始 90 秒休息倒计时，按挂钟时间戳计算剩余时间；结束训练需确认并停止记录。计划被删除时既有会话置空其计划引用并保持完整。
- 训练容量、个人纪录、周完成率（已完成第四个本地切片）：统计只使用本地已结束会话数据；容量为组次重量 × 次数之和，个人纪录按动作取最重组次，周完成率按计划星期对本周到期日的已完成会话数计算。无 schema 变更。
- 规则化渐进建议；疼痛反馈触发安全提示（已完成第五个本地切片）：渐进建议只来自本地已结束会话的规则对比，永不声称专业或医疗结论；疼痛反馈对话框不写任何记录，仅提供停止训练（立即结束会话）、降低负荷、替换动作三项通用安全选项与就医提示。

退出条件：中断后可恢复训练；计时进入后台后时间正确；个人纪录和容量计算单测通过；不安全或未知 AI 动作被拦截。

## Phase 5：隐私、备份与数据可携带性

**目标**：使本地存储方案具备可恢复性和可审计性。（已完成）

任务：

- 隐私中心、数据分类和占用空间（已完成：「我的」页新增「隐私与备份」区块，集中提供加密备份、恢复、CSV 导出与危险区清除入口，并说明数据仅存本机）。
- 加密 `.lfb` 备份、预览、恢复与完整性校验（已完成第一个核心切片）：`LfbBackupCodec` 以 PBKDF2-HMAC-SHA256（默认 60 万次迭代）从用户口令派生密钥，AES-256-GCM 加密，SHA-256 校验和先行快速发现损坏；封套只含盐值/nonce/密文与校验和，口令与数据库密钥绝不写入文件。恢复经 `RestoreLocalFitData` 在单一事务中替换全部数据，任何失败（错误口令、篡改、格式不符）都保持现有数据不变。
- JSON 完整导出及饮食/训练 CSV 导出（已完成）：`ExportLocalFitData` 导出全部 19 张逻辑表（驼峰键 JSON，含导出版本与时间）；`ExportCsvFiles` 通过 `CsvExporters` 生成 RFC-4180 转义的饮食明细与训练组次 CSV（BOM 前缀便于表格软件打开）；文件经 `BackupFileStore`（file_picker SAF 实现，测试用内存替身）由用户选择保存位置。
- 按类型/日期删除、仅删照片、全部清除二次确认（已完成清除部分）：「清除全部本地数据」需手动输入「全部清除」四字确认，按钮在此之前禁用；清除不删除已导出的备份文件。按类型/日期删除与仅删照片推迟到 Phase 6 与媒体功能一同设计。
- 数据库迁移和旧备份兼容测试（迁移测试覆盖 v1→v9；备份封套校验 format/version/kdf/cipher 并拒绝不受支持参数，为未来版本升级预留判定路径）。

退出条件已满足：错误口令、篡改密文与损坏包在单测中全部拒绝且不破坏现有数据；恢复在单事务内执行，中断不产生半套数据；测试通过内存文件存取模拟新设备恢复；口令与密钥不进入备份明文。

## Phase 6：统计与体验完善

**目标**：形成稳定可发布的 MVP。

任务：
