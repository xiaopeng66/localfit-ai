# 2.x 阶段归档（`docs/history/2.x/`）

日期：2026-10-05

## 为什么这里没有文件

2.x 阶段的六份**已完成方案书**（`docs/11`、`22`、`25`、`26`、`27`、`28`）
**按决定原位保留在 `docs/` 下，不物理搬进本目录**。

理由（2026-10-05 实测）：

| 文档 | 代码/测试里的 `docs/NN` 引用数 |
|---|---|
| `docs/28` | 210 |
| `docs/11` | 59 |
| `docs/22` | 51 |
| `docs/27` | 25 |
| `docs/25` | 6 |
| `docs/26` | 0 |

把这些文件搬走，会让 `lib/` 和 `test/` 里 51–210 条注释指向不存在的路径——
**「一半真源在一半在归档目录」比不归档更容易误导新会话**，
而本次整理的目的正是「不被旧文档误导」（`docs/29` §0）。

因此 2.x 采用「**原位 + 统一状态横幅 + 唯一地图**」：

- 每份文档首行横幅：`> 状态：已完成（日期）· 规范效力：无 · 后续以 docs/29 为准 · 文档地图见 docs/INDEX.md`
- 唯一地图：[`docs/INDEX.md`](../../INDEX.md) §2「已完成的方案书（历史，无规范效力）」

1.x 时代的文档（已无代码引用）继续用 `docs/history/1.x/` 物理归档。
