## 1. 复核方法（为什么不复用第三轮自己的测试）

第三轮的测试是我照着**实现**写的（断言它现在长什么样）；复核要回答的是**你当时要的
那件事有没有真的做到**，所以这轮换成三路证据：

1. **独立复核测试**：从需求原文（你的原话）写判据，走**真实链路**（真数据库 → 真仓储 →
   真组件），不复用实现里的 Key 语义假设。数字**自己按克数算一遍**再比对界面。
2. **实帧**：把每个视觉面拍成 PNG，**逐张自己看**（19 张，清单见 §8）。看得见的问题
   测试抓不到——这轮 5 个缺陷里有 3 个是看图发现的。
3. **行为断言**：状态机/交互类（如「一次发送不点两次」「点了重试真的再读」）用断言，
   因为「态」本身没有可拍的静帧。

## 3. 复核抓到并修掉的 5 个缺陷

共同的形状：**第三轮的断言是绿的，但用户看到的东西不对**。

### 缺陷 1（§19）卡头摘要把新食材说了两遍，还搬回了 P/C/F 压缩写法

- **症状**（断言原文：`'鸡蛋水煮'.allMatches(summary).length == 1`，实测 **2**）：
  `米饭 150g、鸡蛋水煮 100g；新建食材「鸡蛋水煮」：155.0 kcal/100g（P13.0/C1.1/F10.6）`
  ——同一件事说两遍，而且 `P13.0/C1.1/F10.6` 正是你在 6c 明确否掉的「挤在一起很丑」的写法。
- **根因**：明细行的「食材类」分支确实排除了被餐引用的 `food.create`，但它**排空之后往下掉进了
  通用 `summarize()` 分支**，那一支没有同样的排除条件 ⇒ 又报一遍。
- **修法**：通用分支加同一道排除；同时「记餐类」分支给本卡要新建的食材标一次
  **「（新建）」**（合并后 `food.create` 不再单独成行，「要先建」这件事必须有一处说出来）。

### 缺陷 2（§19）合并后的食材行**丢了**每 100g 热量与三色点

- **症状**（断言原文：`find.byKey('chat-edit-newfood-dot-0-0-1-0')` 应为 1，实测 **0**）：
  方案 B 的四件套（大热量 + 三色点）原来长在 `food.create` 那一行上；把那一行收进记餐组后，
  信息没跟着走——合并反而让用户看不到这个新食材的热量与宏量。
- **修法**：记餐子条目在「本卡会新建」时带上创建行的营养四件套，走同一套食材行版式；
  Key 用 `chat-edit-newfood-*`（比独立食材行多一层子条目下标，一条记餐两样新食材也不撞）。

### 缺陷 6（§1）未设目标时三宏量右端写「/ 0 g」——一个**编出来的目标**

- **症状**（断言原文：`find.textContaining('/ 0 g')` 应为 0，实测 **3**）：`60 / 0 g`。
- **根因**：`MacroBar.target` 是非空 `num`，调用点写 `targets?.xxxMaxGrams ?? 0`。
- **修法**：`target` 改可空；没有目标就只写当前值、进度条不填。你说过的
  「算不出来就说数据不足，不许给假数字」——这就是那一条。
- **实帧**：`verify-1-no-target`（三块只有 60 / 120 / 40，没有 `/ 0 g`）。

### 缺陷 7（§20）320dp × 2.0× 底行备注被压成**一字一列**

- **症状**（取帧原文 `verify-20-narrow-320-2.0x.png` 第一版）：「食堂二楼」四个字竖排成一列，
  ⋮ 菜单被挤在边框上。**「不溢出」那条断言当时是绿的**——溢出和「丑到读不出来」是两件事。
- **修法**：底行由 `Row` 改 `Wrap` + 备注最小可读宽度（104dp）：放不下就整块换到下一行
  拿满整行宽（菜单留在右缘）。判据补一条**量宽度**（2.0× 下 ≥100dp），不再只量「有没有溢出」。

### 缺陷 8（图片气泡）尾角跑到了**右上**

- **症状**（取帧原文 `verify-4-image-bubble.png` 第一版）：一颗绿钻飞在图片右上角，像误画的
  装饰。而文本气泡是 `right:-3, bottom:-2`（右下），本件文档也写「右下 45° 旋转小方块」。
- **修法**：改成与文本气泡逐字相同的定位；补一条**几何**断言（尾角中心在图片右下部）。
- **变异验证**：把 `bottom:-2` 改回 `top:12` → 断言红（**17 vs 70**）；还原 → 绿。

## 4. 只改「取帧件」、没碰产品的三处

这三处是**我的复核工具**的问题，不是产品的：

1. **17d/17e 循环**：`MaterialApp` 没有 Key，第二轮 `pumpWidget` 复用了同一个 Navigator，
   帮助弹层还盖在页面上 ⇒ 反馈弹层根本没开、`verify-17e-feedback.png` **一直是缺的**。
   改为每轮先卸树。
2. **6d 对话框豆腐块**：`AlertDialog` 的标题/正文走 `dialogTheme`、按钮走
   `filled/textButtonTheme`，这些样式在 `ThemeData` 构建时**冻结**（族为 null），测试引擎
   没有平台兜底 ⇒ 整段 `.notdef` 方框。按本仓既有纪律（`listTile/appBar` 同族同因）：
   **捕获件补族，生产代码不动**。
3. **§3 全屏看图**：占位图是没 child 的 `ColoredBox`（0×0）⇒ 帧里只有黑底和关闭键，
   等于没拍到看图页主体。改成有尺寸的占位块。

1. **超上限说了两遍**：环里一行「超上限 120」，脚注又写「超出 120 kcal」——同一个数字、

   合并成一处也可以，但要不要删由你定。

## 6. 没有实帧的两项（为什么）

- **§2 步数**：三态是**运行时**才决定的（权限被拒 / 设备不支持 / 这次没读到），实帧只能拍到
  其中一态，而恰恰缺的是**你当时看到的那一态**。断言已覆盖全部三条文案 + 「重试真的再读」，
  但你现场的现象（哪一态、有没有文案）仍是定案的前提。
- **§16b 候选去重**：候选弹层要「模型回复 + 6 条历史 + 已存记忆」三样同时在场才能拍到「已存的
  不出现在候选里」；断言（`已存的『不吃香菜』findsNothing` + 新候选 `findsOneWidget`）比静帧
  更准，所以没再为它造一次全页装配。
