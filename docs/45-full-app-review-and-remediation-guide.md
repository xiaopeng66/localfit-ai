## 2. 自治规则

### 2.1 "不要停下来汇报"的准确含义

- **阶段之间 / 阶段内都不停**；只在阶段边界写一次 <200 字进度戳，然后继续。
- **审查阶段缺陷只登记不修**：避免"边审边改"把审查对象改掉、把基线搅乱。
- **进度戳**：每阶段结束（或每 90 分钟，先到者）在
  `docs/evidence/2026-10-20-full-app-review/run-log.md` 追加一行
  `时间 | 阶段 | 已完成 | 正在做 | 阻塞`。这是上下文被压缩后唯一的续跑依据。
- **需要取舍时取默认值并登记**（见 §2.4），不等答复。

### 2.2 阻塞绕行（必须留证据）

| 阻塞 | 绕行 |
|---|---|
| AVD 起不来 / 被误杀 | 清残留进程与锁后重试；仍失败 → widget 测试 + 历史帧替代，登记 `device: blocked` |
| Windows 内存耗尽（OOM） | 关自有 AVD 释放内存重跑；同状态连续 3 次失败才登记 blocked |
| 无真实 AI 凭据 | 契约测试 / mock 端点验证 wire 与解析；**不得**声称"真实 AI 已验证" |
| 需要用户裁决（schema / 21 列 CSV / wire） | 登记 `decision-required`，取最保守默认（不改），继续审其他维度 |
| 主观判断（好不好看） | 与设计稿 + 同组件对照 + 实看帧给结论，标注主观性 |
| 疑似缺陷无法复现 | 登记 `unreproduced` + 尝试次数 + 环境，不升级为 P0 |
| 门禁红但与本轮无关 | 记录基线失败项，用文件哈希证明非本轮引入，继续 |

**只有满足以下任一才允许停**：① 仓库不可读或工具链彻底不可用；② 缺不可推断的凭据/设备且阻塞**全部** P0；
③ 磁盘/权限导致连文档都写不了。其余一律绕行 + 登记 + 继续。

### 2.3 默认决策表

| 场景 | 默认 |
|---|---|
| 修复会动 wire / 21 列 CSV / schema | 不修，登记 `decision-required` |
| 两条实现路径都可行 | 选改动面小、可回滚、可测的 |
| 视觉与设计稿不一致 | 以 `docs/21` 与共享件为准；都无依据则保留现状并登记 |

| 需要新增第三方依赖 | 除非阻塞 P0，否则不新增 |
