## 1. 执行方式（硬约束，优先于一切细节）

1. **连续执行，不中途汇报。** 一次会话内从审查跑到收敛：阶段之间、轮次之间都不停、不等确认、
   不输出「阶段完成」。
2. 唯一的中间记录是 `docs/evidence/2026-10-22-full-review-v2/run-log.md` 的时间戳行
   （供断点续跑，不面向用户）。**最终报告一次性交付。**
3. 需要取舍时取默认值并登记（§6），继续。
4. **只有三种情况允许停**：
   ① 仓库不可读或工具链彻底不可用；
   ② 缺不可推断的凭据/设备，且**阻塞全部 P0**；
   ③ 磁盘/权限导致连证据或文档都写不了。
5. **轮次上限 5 轮**：第 5 轮仍未收敛 → 停，把残留逐条写成 `decision-required` 交用户裁决
   （不允许静默收工，也不允许无限循环）。

## 4. 判据（每阶段 + 收敛）

### 4.1 阶段判据

| 阶段 | 通过条件 |
|---|---|
P1 | `docs/51` §7 的覆盖目标逐格有结论；每条结论可顺着证据路径复现 |
P2 | 报告包含：结论段、覆盖逐格、≥12 项指标、P0/P1/P2 台账（每条挂证据）、未覆盖/not run、与历史对账、已接受项 |
P3 | 每个 P0/P1 一条，字段齐全；触及 wire/CSV/schema 的标 `decision-required` |
P4 | 每条修复有**先红后绿**证据（或隔离变异 + 逐字还原 sha256）；定向回归全绿 |
P5 | 门禁五项全绿 + 设备复验通过 + 指标劣化 ≤10% |
P6 | 见 §4.2 |

### 4.2 收敛判据（「直到没有问题」的准确含义）

同一轮内**同时**满足才停：

1. **P0 = 0 未闭环**（发现即修，修完有先红后绿）；
2. **P1 = 0 未闭环**（未闭环的只能是用户裁决项，且有替代证据）；
3. **本轮新增 P0/P1 = 0**（对比上一轮台账；同一 ID 复发算新增）；
4. **门禁**：`run.py <label> gate` — format 0 改动 / analyze 干净 / 全绿 / exit 0 /
   `changed_during_run: []`，且**连续两次运行都绿**（排除 flaky 假绿）；
5. **指标**：≥12 项与基线对比，无一项劣化 >10%（劣化需有解释并被接受）；
6. **设备**：≥10 类场景实帧通过，APK 与源码同源（构建晚于全部源文件，aapt2 + sha256 核对）；
7. **P2 残留**：全部登记，且每条有「接受/延后」结论（新增 P2 不得静默）；
8. **文档同步**：`docs/21`（若动 UI/Key）、`docs/03`（若动契约）、`STATUS.md`、`docs/INDEX.md`、
   证据目录全部更新。

> 第 1–2 轮通常会有残留；从第 2 轮起，只有**同一轮里 1–8 全满足**才算收敛。
> 若第 5 轮仍未收敛：停，逐条写 `decision-required`，不得自行宣布完成。

### 4.3 数字口径（防「假收敛」）

- 测试数只作参考，不作判据；判据是「同一批断言在修复前后都跑、且修复后不靠放宽断言变绿」。
- 禁止：删测试、`skip`、调大预算、只跑子集冒充全量、mock 冒充设备、用旧日志冒充本轮。
- 每个门禁标签的日志用 `xb` 打开（同标签重跑前先移走旧日志），避免误读旧结果。

## 6. 阻塞与默认动作（不停）

| 阻塞 | 动作 |
|---|---|
AVD 起不来 | 清锁/进程重试；仍失败用 widget 测试 + 历史帧，记 `device: blocked` |
模拟器无外网 | `svc wifi/data enable`，必要时重启并加 `-dns-server 8.8.8.8`；仍不通则 AI 设备侧记 blocked，Host 实测替代 |
内存 OOM | 关 AVD 释放后重跑；连续 3 次才记 blocked |
无真实 AI 凭据 | 契约/mock 验证 wire 与解析；**不得**声称真机 AI 已验证 |
需要裁决 | 登记 `decision-required`，取最保守默认（不改），继续 |
无法复现 | 记 `unreproduced` + 尝试次数，不升 P0 |
门禁红但与轮次无关 | 用文件哈希证明非本轮引入，记基线失败项，继续 |

## 7. 缺陷定级

`P0`：崩溃 / 数据丢失或错算 / 隐私泄露 / 核心流程不可用 / 安全绕过 / 装上一启动就崩。
`P1`：功能不可达或结果错误但可绕过 / 误导文案 / 卡顿 >500ms / 降级未标注 / 静默改写用户数据。
`P2`：体验瑕疵 / 一致性 / 次要性能 / 措辞。
`P3`：优化与重构（不进修复范围）。
定级在 P2 报告阶段一次定死（ADR-035）；静默数据丢失、重复写入、错误结论直接进 P1。
