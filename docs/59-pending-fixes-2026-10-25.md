## 0. 需要用户先裁决的 3 项（阻塞其余部分）

### D-1 未分析的食堂菜是否进菜品库

- **现状**：`lib/features/nutrition/application/add_canteen_dishes_to_library.dart:88`
  ```dart
  if (kcal == null || protein == null || carbs == null || fat == null) {
    skipped++;
    continue;                       // ← 没有营养就不进库
  }
  ```
  而「按菜品记录」只读菜品库（`nutrition_actions.dart:83` 的 `library.watchAll()`）
  ⇒ **用户先建好、还没分析的食堂菜，在记录弹层里永远搜不到**。
- **既有约束**：`add_canteen_dishes_to_library_test.dart:112` 钉着
  「未分析的菜品不得进库」（理由：全「—」的卡会污染营养分母）。
- **三个选项**：
  1. **进库并显示「—」**，卡上标「待分析」；
  2. **不进库，但记录弹层里能搜到**（弹层分两块：菜品库 / 食堂目录未分析）；
  3. 不改，只在弹层加一句「食堂菜需先分析营养才会出现在这里」。
- ✅ **已实施并验证（2026-10-25）**：弹层新增分组「食堂目录（未分析）」+ sealed 结果类型
  `DishPick`；7 条新测试 + **变异验证**（关掉分组 → 4 条红）。
  **实施中修正了原方案的一处不妥**：原写「份量取 `servingGrams ?? 100g` 并记下去」——
  没有营养就记下去等于 **0 kcal**，会污染当天热量（「静默写错事实」）。
  改为**不给直接记**，只如实说明 + 给「去分析」入口（复用既有 AI 分析回调）。
- **影响面**：`DishMealPickerDialog` 增加第二个数据源；`recordByDish` 传参；
  记一笔时的份量口径（未分析菜没有每份营养，只能按 `servingGrams` 或 100g 记）。

### D-2 「换一整套」误报「AI 未配置」—— ✅ **已查清并修复（2026-10-25）**

- **根因（与最初猜测不同）**：不是「配置探测读错源」，而是**那句提示是写死的**。
  `menu_dish_list.dart` 的 `_repickSet()` **无条件**本地重排，并**无条件**弹
  「（AI 未配置；在 AI 对话页「生成今日吃法」…）」——它**从未检查过任何配置**，
  `MenuDishList` 的构造函数里连 AI 服务都没有。配好 AI 的用户因此被告知
  「AI 未配置」，以为配置没生效或链路断了。
- **裁决与实现不符**：`daily_set_repick_test` 文件头记着 D3 要求两条分支
  （已配置 → 走 `aiStarterRequest`；未配置 → 本地重排 + 实话），
  **实现只做了第二条**。
- **已修**：`onAskAiForSet`（`Future<bool> Function()?`）：组合根先查证
  「provider 配置非空 **且** 有 API Key」，只有真配好才注入；`_repickSet`
  优先走它（`true` = 已交给 AI，不再本地重排）。提示文案改为如实描述。
- **验证**：3 条新测试 + **变异验证**（关掉 AI 分支 → 2 条红）。

## 1. 步数检测无法使用

- **现状**：`settings_page.dart` 的步数行只读状态、不请求权限；
  请求动作在今日页步数卡（`steps_card`）。
- **待确认**：用户看到的是「未授权」「设备不支持」还是「状态未知」三种中的哪一种？
- **方案**：
  1. 先加**诊断输出**（设置页步数行显示 `StepsChannel.read` 的原始状态与错误码）；
  2. 按状态分别处理：`denied` → 一键跳系统设置；`noSensor` → 明说设备不支持；
     `unknown` → 加「重试」按钮。
- **判据**：三种状态各有断言；点击「去设置」真的打开 `ACTION_APPLICATION_DETAILS_SETTINGS`。

## 2. 图片点击放大

- **现状**：`ImageMessage`（`lf_chat_bubbles.dart`）只渲染缩略，无点击。
- **方案**：包一层 `GestureDetector` → `showDialog` 全屏 `InteractiveViewer`
  （支持双指缩放），点击/下滑关闭；Key `ai-chat-image-zoom-<index>`。
- **判据**：点击后出现全屏层；`InteractiveViewer` 可缩放；关闭回到列表；2.0× 字号不溢出。

## 3. 带图食堂菜品分析要点两次发送

- **现状**：`app_router.dart` 的食堂「AI 分析」把图片放进 `_pendingImage`，
  但**只预填文字**，用户还要再点发送。用户原话：「点击后只会发送文本，
  图片需要再点一次」。
- **方案**：食堂分析入口改为**一次性发出**（图片 + 文字一起进 `sendImageMessage`），
  或明确把待发图片挂上并立即发送。
- **判据**：从食堂菜点「AI 分析」→ 消息列表**立刻**出现带图用户消息（不需要第二次点击）。

## 4. 食材创建与应用卡片的联动（用户明确描述的流程）

- **用户原话**：「当我点击鸡蛋水煮的应用的时候，应该弹窗提示是否应用创建食材
  鸡蛋水煮，我选择确认后又可以继续应用该早餐添加，而不是我点击应用后，
  因为下边的卡片没有点击应用，导致食物库没有鸡蛋水煮，从而添加失败」。
- **现状**：`meal.create` 与 `food.create` 在**同一张卡的不同组**，
  组级应用互相独立 ⇒ 用户只应用「记一餐」那组 → 食物不存在 → 失败。
- **方案**：
  1. 应用 `meal.create` 时先检查 `items[].food` 是否都存在；
  2. 缺失且**同卡内有对应的 `food.create`** ⇒ 弹确认「要先创建食材 X 吗？」；
  3. 用户确认 → 先应用那条 `food.create` → 再重试 `meal.create`；
  4. 用户拒绝 → 该行失败并如实说明（不静默跳过）。
- **判据（RED 先行）**：
  - 缺失 + 同卡有创建 → 弹确认；
  - 确认后两条都应用成功（`meal` 真的有这条食物）；
  - 拒绝后行显示失败且原因清楚；
  - 缺失但同卡**没有**创建 → 沿用现有「新建食材」修复按钮。

## 7. 已添加的记忆候选仍出现

- **现状**：候选层点选保存后，**同一次会话内再次提炼**会把已保存的又列出来。
- **方案**：保存后记录已存文本（或按 `normalizeAiMemoryText` 比对 active 记忆），
  候选层过滤掉已存在的。
- **判据**：保存 1 条 → 再次提炼 → 该条**不再出现**在候选里；新候选仍出现。
