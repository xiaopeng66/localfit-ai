## 1. RV2-P1-01（已修）：同名食物在记餐搜索里不可区分

**现象**：`记录一餐 → 按食材记录` 搜「米饭」，结果区三行显示
`米饭 / 116 kcal / 100g`、`米饭 / 338 kcal / 100g`、`米饭 / 156 kcal / 100g`，**无品牌**，
三行视觉上几乎一致。真实库四条的 kcal 相差 2.9 倍，点错即静默记错营养。

**根因**：`lib/features/nutrition/presentation/meal_editor_dialog.dart` 的 `_FoodResultRow`
副标题写死 `'${food.kcalPer100g.round()} kcal / 100g'`；`FoodRecord.brand` 存在但从未渲染；
读屏标签也只有 `添加 ${food.name}`。

**为什么不是另一种改法**：
- 不改数据层（`foods.name` 不带品牌）——名称是产品字段，品牌是独立事实，合并会污染搜索与导出；
- 不在搜索排序里按品牌去重——四条是**不同食物**（不同品牌不同热量），去重会丢数据；
- 只改这一行（不改 `FoodCard`）——食物库列表已由 docs/21 §3.11 明确定死「单行三件，品牌退到详情」，
  而记餐搜索是**选择动作**，需要区分度，场景不同、判据不同。

**改法**（一处，`meal_editor_dialog.dart`）：
1. 副标题：有品牌时 `品牌 · N kcal / 100g`，无品牌保持原样（`N kcal / 100g`）；
2. 语义标签：有品牌时 `添加 名称（品牌）`。

**先红测试**：`test/features/nutrition/nutrition_presentation_design_test.dart`
新增「同名食物（不同品牌）在结果行里必须可区分」——插一条 `米饭` + 品牌 `千丰香米`，
搜「米饭」，断言 `find.textContaining('千丰香米')` 与 `find.bySemanticsLabel('添加 米饭（千丰香米）')`。
**RED 见证**：`+23 -1`，失败原因「同名不同品牌的行必须把品牌印出来」。
**GREEN**：同文件 `+33 All tests passed!`（含既有 33 条，无断言改动）。

**同类变体扫描**：`grep -rn "kcal / 100g" lib` → 4 处命中：
- `meal_editor_dialog.dart`（本处，已修）
- `scan_candidate_editor.dart:632`（拍照识餐的本地食物选择 `ListTile`）→ **同样是选择动作、同样缺品牌，同轮修**
- `food_library_results.dart:36`（列表头单位「kcal / 100g」）→ 不是食物行，不涉及
- `text_fit.dart:116`（注释）→ 不涉及

变体修复后 `scan_round7_structure_test.dart` 8/8 绿（其断言 `116 kcal / 100g` 用的夹具无品牌，
文案逐字不变）。

**影响面**：两个纯呈现文件；无数据层、无契约、无 schema、无 CSV 改动（**不触发 decision-required**）。
**回滚**：两处 `git diff` 反向即可（仓库未初始化 git，改法记录在本文件 + `fixes/` 补丁说明）。
**风险**：无品牌条目文案逐字不变 ⇒ 既有精确断言全部保留。
