## 1. 一句话说明

LocalFit AI 没有账号、没有开发者服务器、没有分析/广告/崩溃上报 SDK。你的档案、餐食、
菜单、训练和计划只存在本机加密数据库和应用私有文件里。唯一会离开设备的内容，是你
**自己配置**的 AI 服务在你主动点按某个任务后收到的那一次请求。

## 2. 数据类别（Data safety 表）

| 数据类别 | 是否收集¹ | 是否会出网 | 存储位置 | 加密 | 清除方式 |

| 健康与健身信息：身高、体重、目标、每日目标、测量记录 | 否 | 仅在你主动运行 AI 任务时，按该任务的字段白名单发送必要部分 | SQLCipher 加密数据库 | 有（SQLCipher，密钥在 Keystore/Keychain） | 「清除全部本地数据」 |
| 过敏与饮食约束（dietary labels / allergen avoidances） | 否 | **是（仅当你使用 AI 对话时）**：2026-10-17 起随「可编辑数据快照」发送给你自己配置的 AI 供应商（docs/38 S11——AI 要按它给建议；同一请求本来就发送餐记录/体重/训练计划，**不新增数据接收方**）。本地每日计划 solver 仍读同一份数据 | 同上 | 同上 | 同上 |
| 餐食记录、训练记录与计划 | 否 | 训练计划任务会发送你填写的目标描述文本与本地动作 id/名称 | 同上 | 同上 | 同上 |
| 可编辑数据快照（AI 对话）：**饮食偏好与忌口**（2026-10-17 新增）、**长期记忆**（2026-10-17 新增，可在「我的 → AI 记忆」逐条查看/删除/一键清空，并可整体关闭注入）、目标、餐记录/条目、训练计划、菜品、食堂三级目录、饮水、体重的 **id + 名称 + 关键数值**（2026-10-13：通勤分钟数已随该特性下线从快照移除，见下「路线查询」） | 否 | 仅当你使用 AI 对话时随请求发送（docs/23 §3：让 AI 能引用真实条目提议修改；不含 API Key、不含照片、不含完整食物目录） | 快照本身不落库，只存在于那次请求里 | 快照内容源自 SQLCipher 加密库 | 「清除全部本地数据」 |
| 照片（拍照 / 相册选择） | 否 | 仅餐食识别任务发送**已在本机压缩并清除 EXIF** 的 JPEG | 仅临时目录 | 应用私有目录 | 扫描结束清理 + 「清除全部本地数据」 |

| 内置食物库（随包目录 + CSV 导入行） | 否 | 否 | SQLCipher 加密数据库 | 有 | **「清除全部本地数据」不删**（2026-10-23：导入行也属内置，只有 App 内新建才是自建）；要清走「我的 → 清空内置食物」 |
> **2026-10-21 补充（RV-P2-14）**：应用私有目录里**明文**存放的用户字节不止 `menu_raw/`：
> `chat_images/`（对话图片副本）、`dish_images/`（食堂菜品照片）、`localfit_ai/avatar/`（头像）
> 同样是明文文件（数据库本身由 SQLCipher 加密，但这些副本不在库里）。它们的生命周期：
> `chat_images/` 与 `dish_images/` 随「清除所有数据」整目录删除；头像同；导入菜单原文同。
> 目录内文件不会被备份带走（`.lfb` 只存路径），也不会出网（只有用户主动发图才读盘上传）。

| 位置 | 否 | 否 | 不收集 | — | — |
| 个人信息（姓名、邮箱、电话、账号） | 否 | 否 | 不收集 | — | — |
| 设备或其他 ID、广告 ID | 否 | 否 | 不收集 | — | — |

发往 AI 供应商的请求由你用自己的 API Key 发起、直连你配置的服务，不经过我们。

## 3. 网络出口（Data safety 的「数据传输」）

| 出口 | 触发方式 | 发送内容 | 目标 |
| --- | --- | --- | --- |
| 餐食识别 `meal-estimate.v1` | 你点按识别任务并在披露后确认 | 本机压缩去 EXIF 的 JPEG + 固定指令 | 你配置的 OpenAI 兼容服务 |
| 训练计划 `workout-plan.v1` | 同上 | 每周天数、本地动作 id/名称、目标描述文本 | 同上 |
| 菜单整理 `menu-normalize.v1` | 同上 | 你粘贴的菜单文本、本地候选 | 同上 |
| 今日吃法 `daily-menu-plan.v1` | 同上 | 本地候选与当日信息的 allow-list 字段 | 同上 |
| 常吃搭配 `meal-pairing.v1` | 同上 | 你点名食材经本地匹配后的 allow-list（id/名称/每 100g 宏量）与搭配偏好；不上传餐食历史 | 同上 |

- 应用内**没有任何硬编码的出网域名**（`lib/` 里唯一的 `https://` 是设置页的输入提示）。
  不配置 API Key 时应用完全不出网。
- 明文 HTTP 被两端拒绝：设置只接受 HTTPS Base URL，`AndroidManifest.xml` 设置
  `android:usesCleartextTraffic="false"`。
- 每个任务的字段白名单、合同版本和 prompt/request hash 由
  `test/ai_evaluation/ai_egress_evaluation_test.dart` 固定住（2.0-7c）。
- **供应商协议由你在设置里选择**（`docs/24`）：Chat Completions（OpenAI 兼容）为
  默认，另可选 Responses 与 Anthropic Messages。协议只改变**请求路径、请求体形状、
  认证头、SSE 事件形状**四件事——发送内容与上表逐条不变（egress 评测集按 sha256
  钉住 Chat Completions 的请求体，加协议支持时逐字节未变）。**API Key 只进认证头**
  （`Authorization: Bearer` 或 `x-api-key`），不进 body、不进日志。
- 路线查询：当前**没有任何路线出网**。手动通勤时间曾是唯一的“地点类”输入，已于
  2026-10-13 随通勤全链路下线（docs/32 §3 D10）——列已 drop、对话框与快照段已删，
  route adapter 仍未接线。

## 4. 权限说明（Google Play「权限」/ App Store 隐私清单）

| 权限 / 能力 | 用途 | 拒绝后的行为 |
| --- | --- | --- |
| `android.permission.INTERNET` | AI 请求与用户主动下载的食物目录分片 | 不影响手动记餐、菜单导入、计划与统计 |
| 相机 | **未声明权限**。拍照走系统相机 Intent；系统相机界面由相机应用持有权限 | 仍可从相册选择或手动记录 |
| 相册 / 文件 | **未声明存储权限**。选图/选文件走系统选择器（SAF / PHPicker），应用只拿到你选中的那一个文件 | 仍可手动输入 |
| 位置 | **未声明**（`ACCESS_FINE_LOCATION`、`ACCESS_BACKGROUND_LOCATION` 都不存在，由 `test/privacy` 断言） | 不适用：应用没有任何地点/路线输入（手动通勤已于 2026-10-13 下线，docs/32 §3 D10） |
| 通知、通讯录、日历 | 未声明 | 不适用 |
| 麦克风 / `RECORD_AUDIO` | **未声明**（P10 需求 36 已删除语音输入整族，2026-10-07：录音行、转写服务、`record` 依赖与该权限一并移除；历史库旧语音消息只读兼容，不重录音） | 不适用 |
| `android.permission.ACTIVITY_RECOGNITION`（身体活动 / 计步） | **今日步数**（`docs/29` §P9 需求 34）：读本机计步传感器（`Sensor.TYPE_STEP_COUNTER`）；数值只进本机数据库，不上传，随应用自己的加密 `.lfb` 备份一起走 | 步数卡显示「未授权」并提供去系统设置，其余功能不受影响。**授权状态与撤销入口**：我的 → 数据管理 → 「步数与身体活动」（`docs/30` §2 D9，2026-10-08），行内显示当前状态，点开说明弹层 → 「去系统设置」（`ACTION_APPLICATION_DETAILS_SETTINGS`）。**设备走查已实测（2026-10-08 R8）**：「去系统设置」确实跳到本应用的 App info 页（`com.android.settings`，标题 `localfit_ai`）；状态短词四态实测两态——未授权 →「未授权」、授权后无传感器 →「设备不支持」（**不谎报「已授权」**）| 
| `android.permission.BLUETOOTH_SCAN`（附近设备，**`neverForLocation`**）与 `BLUETOOTH_CONNECT`；legacy `BLUETOOTH` / `BLUETOOTH_ADMIN` 仅 `maxSdkVersion=30` | **电子体重秤前台同步**（`docs/31` S6 需求 47 / D6，2026-10-10）：仅前台、用户主动点「授权并开始同步」时扫描约 10 秒，连接广播**标准体重秤服务**（Bluetooth SIG 0x181D）的秤并读一次体重；读数只进本机数据库并标记来源「秤同步」。**不用于推导位置**（`neverForLocation`），本仓不申请任何定位权限（D6 备注：不加定位权限优先于支持老设备） | 设置页行显示「未授权」+ 说明弹层；拒绝后手动记体重不受影响。**不做后台自动导入**（需要通知 + 前台服务整套基础设施，D6）。API ≤ 30 的设备不申请蓝牙权限、诚实显示「设备不支持」；同日已有体重记录时**默认保留原记录**，覆盖须用户明确选择 |

## 5. 日志

- 应用**不写生产日志文件**：`PrivacyLogger` 在白名单允许的四个指标（结果类型、耗时、
  请求字节数、响应字节数）之外一律默认拒绝，未知 key 的值替换为
  `[REDACTED:not-allow-listed]`；生产代码不构造 `PrivacyLogger`（由 `test/privacy` 断言）。
- 菜单原文、学校、地点、行程、food/menu/exercise ID、健康档案和 AI 正文都不进日志。

## 6. 已知边界与本机无法验证的项

| 项 | 现状 | 处理 |
| --- | --- | --- |
| **麦克风 / `RECORD_AUDIO`** | 未声明（P10 需求 36 删除语音输入，2026-10-07） | 曾由 `docs/22` 阶段 A11 实施，现整族回退：录音行、`record` 依赖、权限与转写服务均已删；将来若恢复，按 `docs/21` §5.7 与本文件同步四件套 |
| **步数权限的应用内开关** | **不做**（`docs/30` §2 D9，2026-10-08） | Android 的运行时权限只能由用户在系统设置里撤销；应用内做「取消授权」开关只会停用自己的读数、撤不掉权限本身，设置页会说「已取消」而系统里权限还在 ⇒ 违背诚实条款。所以设置页只提供状态显示 + 「去系统设置」；应用内停用（隐藏步数卡）是将来可选项，用户本轮没有要求 |
| `menu_raw/` 菜单原文 | 写在应用私有目录，**没有**再叠平台级加密（Android/iOS 沙箱为主） | 记入 2.0-7 余项；若判定必须加密，改用与数据库密钥同源的方案 |
| CSV 导出 | 明文（用户主动导出，用来自己看） | 导出前的提示已说明；不写入备份 |
| 已下载的目录分片 `<supportDir>/catalog/*.sqlite` | 「清除全部本地数据」删除数据库行，但**不删除**这些文件（它们是你自己放进来的第三方数据源，不是 App 生成的缓存） | 若要一并删除，先改 `ClearAllLocalData` 并补测试 |
| 厂商私有 BLE 体重秤（如部分小米秤） | 不广播标准体重秤服务（0x181D），扫不到 | 如实提示「未发现支持的电子秤」，不猜私有协议；**真机对秤验证未做**（无真秤，D6 ⑤ 本轮验收上限 = 通道契约 + 权限流 + 落地规则 + 假设备单测），已做 `flutter build apk --debug` 确认原生通道编译通过 |
| iOS 行为 | 本机无 iOS 真机/模拟器 | 未验证；Keychain、文件与 SQLCipher 适配列入发布顺序第 6 步 |
| 商店表单字段 | 本文是草稿 | 上架前按渠道表单逐项填写，并把提交结果写回 7d 证据 |
| CFCT 镜像的再分发条款 | 上游声明「仅供学习研究」，不是明确许可 | 见 `docs/THIRD_PARTY_LICENSES.md` §4；未查证前不得上架 |

## 7. 用户可见的对应界面

- 我的 → 「数据来源与许可证」：食物数据来源、上游、许可证、是否随包，以及
  「开源组件许可」入口（Flutter `LicenseRegistry` 汇总的依赖许可页）。
- 我的 → 「隐私与备份」：`所有数据仅保存在这台设备` 徽章、加密备份、清除全部本地数据。
- 每次 AI 调用前的披露文案（拍照页、训练页、各 AI 工作台任务卡的发送披露）：说明
  发送什么、绝不发送什么、发往哪个服务；生成过程中可取消。
- AI 对话（docs/23）：对话历史与你**当前可编辑数据的快照**（id+名称+关键数值，见 §2 表）
  随每次对话发送；AI 的修改**只是提议**——必须由你在编辑卡上点「全部应用」才会写库，
  应用前你可以逐条看到将改什么，应用后每条结果（成功/失败原因）都如实显示。
  **2026-10-16 起：对话里带的图片会随那条消息一起发出去**（此前只发文字）。输入区选中图片后
  常驻一行披露（`image-send-disclosure`：会发给哪个服务、供应商与模型在设置里），
  与拍照识别页的 `scan-disclosure` 同一条口径；图片只在用户点了发送键后才离开本机。
  **2026-10-17 起（docs/38 S11）：快照里还包含你的饮食偏好/忌口与「AI 记忆」条目。**
  记忆只存在本机，可在「我的 → AI 记忆」逐条查看/编辑/删除、一键清空，或用
  「对话时使用记忆」开关整体停用（关掉后该段不注入）；写入走 AI 提议 + 你点「应用」
  或页面手写，**不会静默写入**。过敏/目标/身体资料这类信息仍以结构化字段为准，
  协议规则要求 AI 用对应命令修改它们，而不是塞进记忆。
  **2026-10-17 起（docs/38 v2）：对话页顶栏的「从对话提炼记忆」会把最近约 40 条
  对话文本再发一趟给同一供应商**（只为提炼候选；候选**点选才写库**，模型不会
  自行写记忆）。不点这个按钮就不会有这一趟请求。
