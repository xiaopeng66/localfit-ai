**对抗性输入加固（v4135）**

这一版没有新功能，是把「喂给应用的坏数据」全部试了一遍并钉死行为——60+ 条对抗性用例，
覆盖四个层面：

## 1. 食物服务（FoodCatalogService）
- 名字注入（SQL 片段 / `<script>` / 引号 / 控制字符 / 500 字超长）→ 按普通文本存，数据库不损、不出错；
- 超大数值（kcal=10⁹）、负宏量、NaN/∞ 全部拒绝且不落半条；
- 重复提交语义钉死：**同 requestKey 幂等复用**，无 key 则并存（名字不裁定身份，A09）。

## 2. 供应（menu_items）
- 份量注入（负 / NaN / 10⁹）全部拒绝，被拒供应不落库；
- 删窗口级联删供应，但**主食物与历史餐不动**；
- foodId 指向不存在的主食物 → 拒绝，不留悬空外键。

## 3. 备份恢复
- 恢复后逐条供应核对 foodId 必须能解析到真实主食物，绝不悬空；
- 读取口对不存在的 id 返回 null，不崩。

## 4. 餐记录（MealRepository）
- 0 / 负 / NaN 克数在数学层即拒，坏值到不了仓储；
- 未来日期拒绝；NaN 营养快照拒绝（不写库）；
- restore 重复恢复同一餐幂等，不重复行。

另外新增 **`nutrition_math_matrix_test.dart`（30 条数值域矩阵）**：精算（0.1g～5000g、浮点 50 次重复逐位稳定）、单位双向换算往返不漂移、克数/份数/份量未知共 20+ 种非法形态批量扫描、旧菜品假设/负/nan 份量拒绝、供应候选映射只收可信份量项、批量 500 条主食物与 200 餐汇总对账、同事务失败整体回滚、归一数值边界（187.5g 精算 / 2000g 上限 / 2001g 拒绝）。
