**修复：食堂有菜但推荐为空（v4138）**

你真机的情况——食堂目录 8 道菜、7 道已分析，但菜单页「菜品库还是空的」——根因找到了：

**旧供应没有主食物链接**。v4132 的架构升级里，归一（把"有每 100g 证据的旧供应"接进
主库）只在数据库 schema 升级那一刻跑一次。如果你的库升级时这一步失败/中断，或者
这些菜是在旧版本期间新分析的，它们的 `food_id` 就一直是空——推荐/记餐按主库判定
全是「待分析」，于是推荐空了，尽管食堂目录里营养都在。

**修法**：归一改为**幂等可重入**，每次启动自动补跑。台账唯一键保证不会给同一旧键
造第二条主食物；失败只记日志、下次启动再试。

- 有完整每 100g 证据的供应 → 自动建主食物并链接，推荐/记餐立刻可用；
- 只有热量区间的 → 保持待分析（不取中点造数）；
- 没分析的 → 保持待分析。

新增 3 条回归（补链接 / 三次补跑幂等 / 区间不硬造）。

**安装**：覆盖安装后**进一次菜单页或重启应用**，补跑即生效；推荐应恢复。schema 仍为 31。
