**AI 对话「幻影应用卡」**
- 根因：模型回复「点『应用』后才会保存」时，这一轮**根本没输出信封**——
  它把一张不存在的卡当成事实；旧逻辑只检查「用户这句话像不像修改请求」，
  这类话不过保守门，于是永不触发催促，用户只看到一段让人去找卡的散文。
- 修复三处：
  * 新增 `replyMentionsApplyCard`：识别回复在讲「点应用 / 应用后 / 应用卡片」；
  * 升级梯子加第三把尺：回复引用「应用」而**会话里没有待应用卡** ⇒ 自动
    加强催信封 + 失败后给兜底卡；已有待应用卡时这句话是正常对话，不误催
    （回归钉住两个方向）；
  * 协议新增规则 15：没有输出信封就**禁止**提「点应用」，要落库直接给信封。
- 口语识别补词：「加入 / 加进 / 加到 / 录入 / 新增 / 存进 / 保存到 / 补记 /
  补录」也算修改请求（「帮我按每份100g加进去吧」不再漏判）。
- 协议长度超预算（7640 > 7500）：压缩规则 11/12/13 的重复表述至 7484 字，
  语义逐条核对未丢失（registry 测试原句仍命中）。
