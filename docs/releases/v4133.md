**修正应用卡片显示 id + 品牌饮料识别（v4133）**

这一版修的是 v4132 里两个你一眼能看见的问题。

## 1. 应用卡片不再显示一串 id

v4132 里「待你确认」卡片每一行都写成了
`[food:01a16de4-bcde-…] 100 g`——协议要求模型把快照里的 id 原样抄（否则同名歧义会被拒），
但**显示**不该跟着抄。

现在：引用照抄、显示另算。
- 卡片行标题、组摘要、失败原因（含「克数找不到依据」）都显示**食物名**：
  「无糖茶（蜜雪冰城）」「招牌红烧肉」……
- 重启后从库里重读的消息同样解析成人话，不会退回 id。

## 2. 品牌饮料能识别了

你上次说「蜜雪冰城没法识别」：库里没有这个条目时，模型会去抓一个不相干的相似食物，
卡片上又只剩一个 uuid，完全没法核对。

现在：
- 库里没有的菜/饮料，模型会在同一张卡里先 `food.create`（按 AI 估算并标明来源），
  再用名字记餐；毫升按克记（1ml≈1g），并在回复里写清克数。
- 卡片上会显示「蜜雪冰城无糖茶」，你能看清它到底记了什么。
- 如果估算/克数与回复对不上，仍会被数字接地拦下，并**点名是哪个食物**。

真机同款说法实测（`doulor/workbuddy-glm-5.3-flash`）：
```
applied:已保存到食物库「蜜雪冰城无糖茶」（每 100g）；尚未添加到窗口，也未记餐。
applied:已记录加餐，共 1 样。
```

## 其他

- 记餐/挂窗/存库三个意图、份量来源、历史餐快照等行为不变。
- 数据库 schema 仍是 31（本版无结构变更），从 4132 覆盖安装即可。

---

**安装**：下载与本机 ABI 对应的包（绝大多数手机选 `arm64`），覆盖安装。
