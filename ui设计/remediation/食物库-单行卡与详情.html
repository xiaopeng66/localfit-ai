本稿两条硬主张：
① 卡片单行：`[图标 40][名称][环 36]` 共一条水平中线（绿虚线），内边距 12/8 ⇒ 卡高 ≈56dp（改造前 ≈136dp）。环 44 → 36（LfDimens.foodKcalRingSmallSize）。
② 详情弹层三行营养与环心对齐：环那一列只放环（56dp）——环下口径标签移出该列， 否则 `center` 居中的是「整列 72dp」而不是环心（改造前偏 8dp）。三行宏量整块中心 = 环心。
另：canJoinPlan == false 保留为名称后的内联 12dp 警告图标（不加卡高，§4）。

改造前的偏差：环列 = 环 56 + spaceMicro 2 + 标签 14 = 72dp， 比三格那一行（17dp）高 ⇒ 行高由 72 决定，三格被居中到整列中心 （= 环心下方 (72/2 − 28) = 8dp）。红虚线（环心）从这里穿过， 三格文字不落在它上面 —— 正是用户说的「对不齐」。
改造后几何（可写进测试的算式）
· 环列只有环：Column(children: [ring56]) ⇒ 列高 56，中心 28。
· 三行块：行高 17（caption 档）× 3 + 行距 spaceSmall 8 × 2 = 67dp； 块中心 = 67 / 2 = 33.5。
· Row(crossAxisAlignment: center) 且行高由 67 决定（56 < 67）⇒ 环被下推 (67 − 56) / 2 = 5.5dp，此时环心 = 33.5 = 三行块中心 ⇒ 对齐成立。
· 断言（实现时写）：三行块中心 y == 环心 y（±0.5dp）。改造前同一断言为 33.5 vs 25.5 ⇒ 差 8dp。

④ 不可加入计划：内联 12dp 警告图标（不加卡高）

改造后 · 营养不完整条目360dp
🥤 某目录饮品⚠ —
🍞 帝亚 全麦小吐司面包片 424
为什么保留：canJoinPlan == false 是功能事实 （docs/07 §9.3：能搜到不等于能进计划），进计划时会被拒。 全删会变成「点进去才知道不能加」。图标 12dp （Icons.error_outline，c.warning 色）内联在名称之后， 带 Semantics(label: '营养不完整，不可加入计划')。
不加卡高：它住在名称那一行的行内（行高仍由图标 40 决定）， 原型卡仍是单行 ⇒ 行高口径不变。名称很长时它随省略号一起被裁掉 （可接受：详情弹层里仍有「营养不完整，暂不可加入确认计划」整句）。
对比：改造前是独立第五行（⚠ 营养不完整 · 不可加入计划）， 带 spaceTiny 4dp 间距 + 14dp 行高 ⇒ 让那张卡比同列表的其他卡高 18dp。 单行化后所有变体等高，SliverPrototypeExtentList 的行高口径 反而更简单（原型 = 真卡形态）。
详情里仍说整句：弹层底部「营养不完整，暂不可加入确认计划」 （LfText.label muted）保留不动 —— 图标负责列表层的可扫视， 整句负责详情层的可理解，两者并存、互不替代。
详情弹层其余不动：品牌 + 自建/内置徽标（头部第二行）保留； 编辑/删除行动行保留（仅自建条目）。用户说「点击后才显示详细的三营养数据」—— 品牌与来源本来就是详情级信息，正好留在这一层。
