① 需求 20 首行 crossAxisAlignment: start → center；并把环下标签移出首行（改为首行下的一行右对齐 文本）⇒ 图标 40 / 名称 / 环 44 三件的心同落在首行中线（距卡内容顶 22dp）。行块高度不变（44 + 2 + 14 = 60dp）。

② 需求 22 环下标签 每 100g → kcal/100g；缺热量时整格换 无热量数据（卡 3）。 环心仍只印数字：44dp 环内孔 36dp，288 kcal 要 FittedBox 缩到 <9px（比环下 10px 标签还小）， 数字反而不再是最大声的那一层。

③ 需求 23 满刻度说明只出现一次（列表头脚注）：环 = 每 100g 能量密度 · 满刻度 900 kcal/100g。 与「每卡写一句 满刻度 900」相比：同一常量重复 50 次是噪声，且要多占名称列的宽；环下标签只承担「每行都会变」的单位。

④ 需求 21 宏量行恒为三格（Row + 三个 Expanded，顺序 蛋白质 → 碳水 → 脂肪）， 缺值与 0 都写 0g（卡 2 的脂肪、卡 3 的碳水）—— 改造前缺项被跳过、剩余格重新分宽，三列逐行错位。 判据要改成显式三态：nutrientOrMissing 现在把 0 当缺失，不改就写不出 0g。

⑤ 需求 24 + 26 品牌：裸 10px 文本 → 带边框 chip（透明底 + 1px mint-300 描边 + mintText 字）挪到左下； 自建/内置徽标挪到右下。两者同高（23.4dp）同字号（11 w500）同圆角（8）：带框那侧把描边的 1px 从内边距里让出来 （Padding(7,3) + Border.all(1)），否则比实底那侧高 2dp。新增 LfBadge.outlinedBrand 变体（与既有 dashed 同源色，只把虚线改实线），不新造第 8 种标签形态。

⑥ 需求 27 卡内底部内边距 12 → 8（EdgeInsets.all(12) → EdgeInsets.fromLTRB(12,12,12,8)）；上/左/右与卡间距不动。

⑦ 保留第四行（卡 3）：⚠ 营养不完整 · 不可加入计划 只在营养不完整时出现，与 0g 并存 —— 0g 是显示约定（缺值与 0 都写 0g，让三列不位移），这一行才是「这条数据不完整」的事实承载者。 两者缺一不可：只有 0g 会被读成「真的没有碳水」，只有警告而不写 0g 又会让三格错位。

备选（评审可改）：若只做最小改动（把 start 改 center、标签留在环那一列）， 环列高 44+2+14 = 60dp，行内居中的是「整列」⇒ 图标/名称被压到 30dp 中线、环心仍在 22dp（差 8dp = 标签半高）。 本稿取「标签移出首行」，因为需求原文要的是三件共线；两种写法的行块高度都是 60dp， SliverPrototypeExtentList 的行高口径不变。

环列定宽 44 → 50dp（实现细节，随 ② 一起改）：kcal/100g 宽 ≈48dp、无热量数据 宽 50dp， 都超过 44dp 环宽；定宽取 max(44, 50) 并右对齐 —— 否则「环 + 标签」的宽随卡片漂移，名称列宽与环的横坐标都不固定。

头部保持文字品牌（本稿裁决）：抽屉头部是 食物名 + 品牌 · 徽标 一行， 品牌在这里不改成带框 chip —— chip 是为卡底行「左右两角要区分」而生的；抽屉头部没有第二角要让， 与徽标同字号（11 w500）同行的文字已经够用。一致化落在环的几何、三格的固定与 0g 口径上，不复制 chip。

缺数据的两处口径分开：环里写 — + 环下 无热量数据（事实判断：没有热量数据）， 而三格克数行照写 0g（显示约定：三格永不缺位）。两者不矛盾 —— 前者说「这一项没有」， 后者说「这一格在，值是 0」。

行动行：只有自建条目渲染 编辑（mintText）与 删除（error 色）两个文字按钮， 各占一半宽，两件都先关掉本层再交给调用点（弹层正显示着将被改掉的数据）；内置条目没有写入口，这一行不出现。
