③ 确认弹层 · 有引用（记录 / 菜单匹配 > 0）

清空内置食物数据？

将删除 49,444 条内置食物（自建食物保留）。 有 12 条饮食记录引用了这些食物：记录本身保留，其中的食物会被清空。 有 3 条菜单匹配会移除（菜品行保留，菜单页会重新给建议）。 设置、AI 配置与照片不受影响；此操作不可撤销。

取消 清空内置食物数据

弹层里的数是现算的：点开时跑 ClearBuiltinFoods.preview() 取三组真实计数（内置食物 N / 引用它们的餐次条目 M / 菜单匹配 K），不是概览里的旧快照 ——概览可能是几分钟前加载的。文案按 0/非 0 拼句：M 或 K 为 0 的那句整条不提， 不写「0 条记录会受影响」这种噪音。

两枚动作都是文字按钮（与「清除所有数据」同一条既有形式， §3.8 B7）：取消 LfTextButton 在左，销毁动作 LfDangerButton 在右——error 字色，不铺实心底。执行中变「正在清空…」+ busy + 两枚都禁点； 失败则复位并在正文下给一行红色说明（同「清除所有数据」的失败处置）。

键：clear-builtin-foods-body（正文）· clear-builtin-foods-confirm（销毁动作）。

一次动作三个后果都在界面上落地：① 计数行从「49,447 条（自建 3 条）」 刷成「3 条（自建 3 条）」——走既有的 _refreshOverviewAfterFoodWrite() 就地重读（弹层返回不触发 TickerMode，设备上已实测过「计数停旧快照」这个坑）； ② 新行自己消失（库里已无内置行）；③ snackbar 报真实结果 （deletedFoods / unlinkedMealItems），M = 0 时那句不提。

幂等与竞态：确认那一刻库若已被别处清空（结果 0/0/0）， snackbar 照实说「没有内置食物可清空。」——用例本身幂等，重跑安全。

本稿明确不做的（逐条）：① 不做「清空 + 立即导入」一步到位向导——新表头（用户提供的 结构文件）未到，重建那半条流程（T11 验收 3/4）落地时再谈是否合并；现在清空后重新导入走 既有入口（「添加食物数据 → 从 CSV 导入」）。② 不用 AppSheet.showForm 的 打字确认（「清除所有数据」那种）——那条是「不留任何用户字节」的量级；本动作只删随库数据， 记录与自建都留住，error 字色的销毁动作 + 三组数字 + 「不可撤销」是相称的强度。③ 不给行加条数副标题 （条数在上一行，第二处数字就是第二个会过期的真值）。 文案口径：不出现 "CSV"（D17），不写「恢复出厂」这类不存在的语义。
