# LocalFit AI 界面升级稿 · 第六轮

状态：HTML 交互设计提案，尚未落地 Flutter。本轮只新增和调整本设计目录及指定临时验证目录，不修改真实 App、数据契约或旧版设计。

## 打开设计稿

- `overview.html`：今日、饮食、AI 助手、训练、我的五页并排总览，适合先看整体方向。
- `index.html`：可点击的交互稿。顶部可切换 360 / 390 / 430px 设计宽度、深浅色与空数据。
- 同目录的 `styles.css`、`model.js`、`app.js` 需一起保留。可直接打开 HTML，无 npm 安装、构建、在线字体或图片依赖。
- 本次本地预览地址为 `http://127.0.0.1:18766/overview.html` 和 `http://127.0.0.1:18766/index.html`，需预览服务保持运行；服务停止后仍可使用本地文件。

顶部工具与两侧说明仅用于设计评审，不是新增的 App 设置项。总览里的五个预览各自拥有独立演示状态；需要跨页面体验时，使用交互稿底部的五标签导航。

## 设计方向

让记录更轻，让信息更清楚。沿用薄荷绿、白色卡片、五标签导航和营养配色；升级来自排版主次、留白、数字对齐和更直接的操作路径，而不是叠加装饰、渐变或更多卡片。

### 紧凑设计系统

- 浅色：画布 `#F7F9F8`，卡片 `#FFFFFF`，正文 `#1A201D`，次正文 `#64766E`，品牌绿 `#2FBE8F`，动作深绿 `#187653`，浅绿 `#E4F6ED`。
- 深色：画布 `#0F1412`，卡片 `#171E1A`，正文 `#EAF2EE`，次正文 `#A0B4AA`，品牌绿 `#4ED9A6`。
- 蛋白质橙 `#FF8A65`、碳水黄 `#FFC94D`、脂肪紫 `#B39DDB` 保持营养语义；饮水单独使用蓝色。
- 交互稿优先使用本机 Microsoft YaHei UI / Microsoft YaHei / PingFang SC 等系统字体，数字启用 `tabular-nums`，不下载字体。
- 页面标题 26px，主要能量数字 36px，正文以 14px 为主，辅助文字以 11–12px 为主；密集图表刻度更小。正文左对齐。
- 以 390px 为基础，提供 360px 和 430px 预览；页面边距 16px，常用卡片圆角 16px、浮层 24px、按钮全圆角。常用按钮高度至少 44px，确认按钮 48px；密集体重柱条不承诺逐格 44px 点击宽度。
- 今日页的识别点是「餐盘环 + 数字分栏」，其余页面围绕各自任务组织，避免五页重复同一张大统计卡。

### 五页重点

| 页面 | 本轮整理 |
| --- | --- |
| 今日 | 能量与宏量营养优先，体重趋势、AI 创作、餐食、饮水和步数依次展开。 |
| 饮食 | 保留记录 / 菜单 / 食物库，分别承载已吃事实、每日菜品推荐与食物营养资料。 |
| AI 助手 | 中央入口直接进入对话，输入与照片入口靠近底部，训练草案明确区分应用和忽略。 |
| 训练 | 近七天统计、每周安排和今天的开始操作集中呈现，进行中的训练可继续。 |
| 我的 | 身体与目标、AI 与数据、食材与设备、关于分组，清除数据独立确认。 |

初步方案曾考虑大幅绿色渐变与食物照片。对照既有反馈后舍弃：大色块不符合用户偏好，图片会降低食物库扫描密度，且现有应用没有可靠的逐食物图片来源。最终使用白底摘要、语义色和本地线性图标。

## 可体验的交互

- 五页导航、饮食子标签、训练计划 / 历史切换，深浅色、设计宽度与空数据预览。
- 记录体重、同日覆盖、周 / 月逐日图；增加饮水；修改演示昵称、饮水和步数目标。
- 食物名称 / 品牌搜索与分类、查看营养、按克数记录餐食、删除并撤销；空库导入明确标示的八条示例食物。
- 菜单里的推荐切换与候选查看；选择食用克数、确认餐次后，将演示菜品记录为已吃。
- AI 预设对话、六个创作入口、训练草案应用 / 忽略；应用才加入演示训练计划。
- 查看计划和训练日、手动创建演示计划、开始训练、填写重量与次数、稍后继续、确认结束并查看历史。
- 信息说明弹层、训练详情收起 / 展开、显式清除演示数据确认。

相机、相册、实际 AI 调用、文件导入导出、加密备份恢复、硬件权限、秤连接、更新检查等入口只展示说明，不执行真实任务。徽章、完整资料字段及其他二级编辑器并未全部复刻；这不是删除对应 App 功能的决定。

## 保留的功能边界

- 五个主入口不变，中央 AI 仍是对话；今日的 AI 创作是二级入口。
- 饮食「菜单」指本地已分析菜品的每日推荐，不是食谱收藏或可复用套餐。地点 → 窗口 → 菜品的维护仍为次级入口。本稿的候选固定为示例，不重写实际推荐算法。
- 六个创作入口沿用现有名称：解析学校菜单、分析菜品营养、生成今日吃法、这道菜怎么吃、训练计划、常吃搭配。它们开启对话，不恢复独立任务执行页。
- 今日吃法仅是对话建议，不自动写入饮食事实；训练草案须明确应用后才加入计划。
- 新装食物库为空，不冒充内置数万条食物。实际 CSV 的 21 列及旧 8 列兼容契约保持不动；本稿不解析用户 CSV。
- 体重周视图七格，月视图覆盖当月；四档坐标，缺失和未来记录保持空槽，不插值补造体重。
- 新训练只允许今天匹配的计划日开始，其他日期可查看；已经进行中的训练可继续。
- 训练消耗保持「—」。本稿不计时，新完成的演示训练时长为 0 分钟并明确提示，不能当作真实计时结果。
- 导出饮食记录、导出训练记录、导出食物数据三个名称分别保留；`.lfb` 加密备份、39 表契约与真实持久化不变。
- 小米秤接口仍未适配，不虚构权限、连接或设备测量成功。

## 演示数据与隐私

饮食、体重、步数、计划和昵称均为演示数据，固定演示日期为 2026-10-13。状态只存在于当前网页内存，刷新即复原；不读取或写入 LocalFit AI 数据库，不采集 API key，不调用 AI 或外部服务。预览页常驻演示声明。
