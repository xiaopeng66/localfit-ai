# LocalFit AI 第七轮设计预览

在熟悉的 LocalFit 上，向前一步。本轮整理既有界面的比例、信息层级与操作位置，不另建业务系统。

## 本轮细节精修

[重点界面并排预览](details.html)集中展示食物库、食物详情和动作库；[五页总览](overview.html)仍保留原五个入口。

- 食物库恢复原生十类 SVG 资产、40px 图标位、单行名称与36px热量环，去掉多余第二行与箭头。
- 食物详情恢复56px / 6px热量环与三行营养的垂直中心对齐；每100g、1000kcal满刻度说明放在整块下方。可编辑样例保留编辑与二次确认删除，只读条目不开放修改；不改变已记录餐食的快照。
- 详情保留“记录这份食物”：预选当前食物，默认晚餐，再按填写克数换算。营养完整且允许记录的只读条目也能记录餐食；营养不完整或明确禁止记录的条目不开放入口，点击与提交时仍会校验。
- 编辑改名后关闭详情，焦点按稳定食物 ID 回到原列表项；条目被删除或被搜索过滤时，回退到主内容区。
- 动作库恢复为二级完整页与双列卡片；按肌群区分图标、按器械区分背景，支持搜索叠加筛选、详情与同肌群替代动作原地切换。新增动作只保存在原型目录，难度未知就如实显示。
- 原有上下箭头定义没有反转。本轮改用更明确的文件导入/导出图标与方向说明，不交换本来正确的定义，不解析真实文件。
- 搜索、卡片、详情与设置行间距一起调整；不减少今日、饮食、我的、训练中的任何现有图表。

可直达 `index.html?page=nutrition&tab=foods&food=milk` 与 `index.html?page=training&view=exercise-library`，均可追加 `theme=dark`、`width=360` 或 `large=1`。

## 入口与三个方向

- [三方案对比](compare.html)：同屏对照今日、饮食记录、我的。
- [A 五页总览](overview.html)：依次查看今日、饮食记录、AI 助手、训练、我的。
- [A 完整主稿](index.html?variant=a&page=today)：进入单个手机稿查看完整交互。

| 方案 | 重点 | 定位 |
| --- | --- | --- |
| A 原版精修 | 原比例保留 / 局部精修 | 推荐方向，完整交互主稿 |
| B 健康仪表台 | 环居中 / 更大绘图区 | 版式对照 |
| C 每日节奏 | 当天记录顺序 / 操作就近 | 版式对照 |

**B/C 为版式对照；完整交互见 A 主稿。** 三方案不是三套独立的业务实现。

## 预览壳与参数

`compare.html` 与 `overview.html` 共用 `studio.css`、`studio.js`。壳使用白与雾白底、低饱和薄荷品牌色、系统中文字体；不使用远程资源、字体、框架或图标依赖。

- 默认手机视口为 **360 × 900 px**，浅色主题、样例记录；对比页默认展示“今日”。
- 宽度可以选择 `360`、`390`、`430` px，iframe 视口与外框同宽、高度始终为 `900` px，不做缩放。
- 对比页为固定宽度的三栏，空间不足自动换行；单框仍放不下时允许横向滚动。五页总览始终横向排列，可横向滚动。
- 原生下拉框支持键盘操作，控件高度至少 44 px，链接与焦点状态可见；iframe 各有页面与方案标题，滚动区可通过键盘聚焦。
- 宽度、手机主题、空状态工具作用于**当前 document 内所有 iframe**。对比页的页面选择也同步作用于三个方案；总览页保留各自的五个页面，不随其他页面参数改成同一页。
- **每次更改工具都会重设全部 iframe 的 `src`，重新载入并重置框内操作与临时记录。** 这一行为在页面工具旁持续提示，变化后通过状态区域再次说明。不同 iframe 的样例状态独立，不共享操作或数据；两个壳页面之间也不共享状态。
- 工具中的深色选项只影响手机稿，壳仍保持浅色，避免干扰方案比较。
- 禁用 JavaScript 时工具不可操作，HTML 中的默认预览与完整稿链接仍保留。

嵌入格式：

```text
index.html?embed=1&variant=a&page=today&width=360&theme=light
index.html?embed=1&variant=b&page=nutrition&width=390&theme=dark&empty=1
```

| 参数 | 可选值 | 壳默认值 |
| --- | --- | --- |
| `embed` | 嵌入时为 `1`；完整稿链接不携带 | iframe 使用 `1` |
| `variant` | `a` / `b` / `c` | 对比页各一框；总览全部为 `a` |
| `page` | `today` / `nutrition` / `ai` / `training` / `settings` | 对比页 `today`；仅提供今日、饮食记录、我的三个选择 |
| `width` | `360` / `390` / `430` | `360` |
| `theme` | `light` / `dark` | `light` |
| `empty` | 空状态时为 `1`；样例记录时省略 | 省略 |

两个壳也可用 URL 的 `width`、`theme`、`empty` 初始化工具；`compare.html` 另支持 `page=today|nutrition|settings`。非法参数回到上述默认值。操作工具不会保存本地偏好或修改浏览器地址；刷新按当前 URL 重新初始化。

每框下方完整稿链接以 `index.html?variant=...&page=...` 开始，脚本启用后继续携带当前宽度、主题及可选空状态参数，不带 `embed`。

## 图形保留清单

以下为本轮应保留的图形及表达约束，也是后续视觉与交互验收清单；列出不等于已经通过验收。

### 今日

- 今日热量环与宏量营养素图形，保持热量、目标和宏量之间的可读关系。
- 体重周视图为**周一至周日 7 槽**；月视图按月份为 **28–31 槽**，不把缺失日期压缩拼接。
- 体重图保留**四刻度虚线**与清晰日期轴，缺失记录不补造数据。
- 饮水、步数保留进度条；下一餐保留就近查看或记录入口。

### 饮食记录

- 日期短柱与七日趋势目标线。
- 每 100 g 密度图，以 **1000 为满刻度**；保留 **36 环**图形表达。
- 估算信息与已确认事实分开呈现；保留“确认估算项数”的明确提示。

### 我的

- BMI 分档与 BMR 区间图形。
- 饮水环与目标关系。
- 成就保留铜、银、金、锁定状态与进度，不只剩奖章名称。

### 训练

- 7 日分钟图、周安排与组数。
- 4 周容量图与肌群容量分布。
- 不将尚未记录的训练显示成已经完成，不补造消耗或容量。

## 业务边界

- **旧业务契约不动**：本轮为 HTML 设计预览，不迁移真实应用业务、数据结构或持久化流程。
- **仅内存样例，刷新恢复**：示例输入、记录和切换只影响当前预览，不读取或修改 App 数据，不作为健康事实保存。
- 不接真实 AI 服务，不打开真实相机，不配对或读取真实设备。
- 不接真实 CSV 导入导出或备份恢复；相关界面只用于说明现有功能位置与演示边界，不承诺实际数据迁移。
- AI 建议、估算、待确认项与用户已记录事实应保持区分；本稿不提供医学诊断。

以当前 Flutter 实现为依据，只在 HTML 原型中表达，不改动原生组件：

| 图形 | 当前实现依据 | 本稿口径 |

固定演示日为 **2026-10-13**，并非系统当天。摄入、趋势、容量均由内存记录计算；基础代谢1430、目标区间1700–1900、成就进度为明确的示例资料/历史快照，不冒称从本次记录自动推导。水量界面以一位小数显示升，因此1250ml显示约1.3L。

## 可以体验的操作

- 饮食新增、删除与撤销；日期选择；食物搜索、分类与详情；详情预选食物后按克数记录；菜单换一个、候选及按克数加入餐次。食物库中保存记录只切回演示今天，不自动切换到“记录”标签。
- 饮水+250ml、体重录入、周/月切换及有效柱条浮窗。
- AI六类创作先填写描述，再进入离线演示对话；训练草案明确应用才写入本页计划，忽略不写入。
- 计划查看、当天开始/继续、逐组记录、结束训练；原型不运行真实计时，新完成训练显示0分钟，消耗为“—”。
- 动作库搜索与肌群筛选、详情中的同肌群替代、创建本页动作。小规模内存样例使用同步筛选，不模拟原生数据库的300ms防抖与加载过程；新增目录动作不会改变已有训练计划、容量或肌群统计。
- 个人昵称及饮水/步数目标可编辑；其余设置入口保留并说明真实功能边界。

`index.html` 额外支持 `tab=records|menus|foods` 与 `large=1`。放大文字只是原型自身字号预览，**不等同系统字体200%缩放或完整无障碍认证**。
